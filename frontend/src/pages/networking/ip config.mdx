Understanding and managing IP addresses is the foundation of networking on Unix and Linux systems.
In this section, we'll focus on viewing interfaces, checking IP addresses and assigning temporary addresses for testing.

## Viewing Network interfaces
The modern command to inspect interfaces is `ip` (Preferred over the older `ifconfig`)

<CodeBlock language="shellsession" code={`user@machine:/$ ip link show\n1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN mode DEFAULT group default qlen 1000\n  link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00\n2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP mode DEFAULT group default qlen 1000\n  link/ether 00:15:5d:4b:89:84 brd ff:ff:ff:ff:ff:ff`} highlightLines={[4]}/>

* `lo` -> Loopback interface (used internally, equivalent to ip `127.0.0.1`)
* `eth0` -> first Ethernet interface
* `UP` -> interface is active
* `mtu` -> maximum transmission unit (packet size)

*Note that eth0 can vary some times. Be sure to check that your interface is eth0. If not, use whatever thats there.*

## Checking IP addresses

To see assigned IPs, use `ip addr`(can be shortened to `ip a`)

<CodeBlock language="shellsession" code={`user@machine:/$ ip a\n1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000\n  link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00\n  inet 127.0.0.1/8 scope host lo\n     valid_lft forever preferred_lft forever\n  inet 10.255.255.254/32 brd 10.255.255.254 scope global lo\n     valid_lft forever preferred_lft forever\n  inet6 ::1/128 scope host proto kernel_lo\n     valid_lft forever preferred_lft forever\n2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP group default qlen 1000\n  link/ether 00:15:5d:4b:89:84 brd ff:ff:ff:ff:ff:ff\n  inet 172.29.26.129/20 brd 172.29.31.255 scope global eth0\n     valid_lft forever preferred_lft forever\n  inet6 fe80::215:5dff:fe4b:8984/64 scope link proto kernel_ll\n     valid_lft forever preferred_lft forever`} highlightLines={[12]}/>
The highlighted line shows the IPv4 address of `eth0`, `172.29.26.129/20`, which has the broadcast address(`brd`) of `172.29.31.255`.
`Scope` refers to the range of visibility (global vs link-local).
Since `inet` refers to IPv4, `inet6` refers to IPv6.

## Assigning IP Addresses Temporarily
You can assign an IP to an interface (will reset on boot) using `ip addr add`. This requires root or `sudo` permissions.
<CodeBlock language="shellsession" code={`user@machine:/$ sudo ip addr add 192.168.1.50/24 dev eth0\n\nsudo ip link set eth0 up\n`}/>
Ensure your network interface is UP.
* `ip addr add` -> add IP
* `dev eth0` -> specify interface
* `ip link set up` -> enable the interface
To remove it, you run the same command but instead of `ip addr add`, it's `ip addr del`.
<CodeBlock language="shellsession" code={`user@machine:/$ sudo ip addr del 192.168.1.50/24 dev eth0\n`}/>
You will need to use `ip a` to verify changes as these commands do not print any output.

## Viewing Routes
Check the routing table to see how packets are forwarded via `ip route show`.
<CodeBlock language="shellsession" code={`user@machine:/$ ip route show\ndefault via 172.29.16.1 dev eth0 proto kernel\n172.29.16.0/20 dev eth0 proto kernel scope link src 172.29.26.129`}/>
* `default` -> default gateway
* `172.29.16.0/20` -> local network route

## Quick Reference
<CodeBlock language="shellsession" code={`user@machine:/$ ip link show # list interfaces \nuser@machine:/$ ip addr show # show IP addresses \nuser@machine:/$ sudo ip addr add # assign IP temporarily \nuser@machine:/$ sudo ip addr del # remove IP \nuser@machine:/$ ip route show # view routing table`}/>
